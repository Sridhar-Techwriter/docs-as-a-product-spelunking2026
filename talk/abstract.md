## Title

Docs-as-a-Product: Engineering a Self-Service Developer Experience for Workday's Open Platform

## Abstract

For an Open Technology Platform to scale successfully, it must be inherently self-service. When external developers, partners, or internal teams encounter friction in our APIs, webhooks, or cloud deployment models, it directly delays integrations and compromises customer trust. Traditionally, technical documentation is treated as a manual, reactive afterthought. This session challenges that status quo, introducing a Docs-as-a-Product (DaaP) framework tailored directly for Workday's FY27 platform goals. We will look beyond standard user guides and demonstrate how treating documentation as a core engineering deliverable, using automated OpenAPI spec-driven pipelines and modular developer portals, transforms the Developer Experience. Through a live demonstration of a CI/CD automated documentation pipeline, attendees will see how code changes can instantly update public-facing guides without manual human typing. Attendees will walk away with actionable strategies to eliminate manual content overhead, slash partner onboarding times, and protect customer trust. Ultimately, this session proves how a modern documentation architecture allows our open platform to scale exponentially in FY27 without a linear spike in engineering support costs.

## Calls to action

1. **Apply an Automation Technique** — Feature and platform engineers integrate OpenAPI/AsyncAPI specs directly into build files so code changes auto-generate accurate docs.
2. **Adopt a New Definition of Done (DoD)** — Product Managers redefine "done" to include automated, self-service documentation.
3. **Spark an Architectural Conversation** — P&T leaders shift budget/mindset toward self-service documentation tooling for ecosystem scaling.

## Audience

Developers, Software Engineers, Architects, Product Managers, and Technical Writers across the P&T organization — anyone building, shipping, or maintaining Workday's APIs, developer tools, and platform infrastructure.

## Format constraints

- Lightning talk: **~15–20 minutes**, including a short live demo and Q&A buffer.
